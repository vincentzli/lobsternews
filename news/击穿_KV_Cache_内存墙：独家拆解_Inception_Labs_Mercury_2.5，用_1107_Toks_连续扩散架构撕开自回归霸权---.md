# **击穿 KV Cache 内存墙：独家拆解 Inception Labs Mercury 2.5，用 1107 Tok/s 连续扩散架构撕开自回归霸权**

---

过去近十年，生成式人工智能的狂飙突进始终背负着一道沉重的微架构“系统税”：自回归 Transformer。

从 OpenAI 的 GPT-4o、Anthropic 的 Claude 3.5 Sonnet，到 Meta 的开源旗舰 Llama 3.3，当代前沿的大语言模型在生成文本时都遵循着同一个高度串行的机械节拍：

$$P(w_1, w_2, \dots, w_T) = \prod_{t=1}^T P(w_t \mid w_{<t})$$

每一个新 Token 的吐出，都强制要求模型在数百层神经网络中执行一次独立的前向传播，并沿着高带宽内存（HBM）反复读取与扩充历史键值缓存（Key-Value Cache，即 KV Cache）张量。

如今，这一铁律正被打破。

由斯坦福大学扩散模型先驱 Stefano Ermon、加州大学洛杉矶分校（UCLA）教授 Aditya Grover 以及康奈尔理工学院教授 Volodymyr Kuleshov 联合创办的 **Inception Labs**，在获得来自 Menlo Ventures、NVIDIA NVentures 以及知名天使投资人 Andrej Karpathy 的 5000 万美元注资后，正式发布了新一代大模型 **Mercury 2.5**。

在商用 GPU 上，Mercury 2.5 跑出了单流（Single Stream）每秒 **1107 个 Token** 的吞吐极速，支持 **260K** 的超长上下文窗口，并在包含 MMLU-Pro 在内的综合学术基准测试中取得了最高 **89.4%** 的顶尖得分。它完全绕开了自回归模型“从左到右、单字迭代”的生产流水线，采用非自回归的连续扩散机制，直接在整段文本序列上并行去噪成型。

这一架构的落地，瞬间在硅谷 AI 实验室和芯片硬件产业界引发了一场深水炸弹级的思辨：Inception Labs 真的彻底击穿了困扰硬件工程界七年之久的内存墙吗？面对离散符号系统与严密的确定性多步推理，连续扩散模型究竟能走多远？

```
传统自回归 TRANSFORMER（内存带宽严重受限 / Memory-Bandwidth Bound）
Step 1: [Token 1] ───┐
Step 2: [Token 1, Token 2] ───┼─► GPU 算力闲置，时钟周期在等待 HBM 传输 KV Cache
Step 3: [Token 1, Token 2, Token 3] ───┘   （算术强度通常 < 1 FLOP/Byte）

非自回归扩散架构（完全释放硬件计算吞吐 / Compute Bound）
Pass 1: [░ ▒ ▓ █ ▒ ░ ▓ █] (全局语义轮廓粗胚) ──┐
Pass 2: [▓ █ █ █ █ ▓ █ █] (句法结构细化填充)  ├──► 全面打满 Tensor Core 运算流水线
Pass 3: [Token 1, Token 2, Token 3, Token 4]  ──┘   （高维度矩阵乘法 GEMM，高 TFLOPS 饱和）
```

### 微架构危机：被勒死在总线上的自回归解码

要理解 Mercury 2.5 的工程革命性，必须首先解剖当下加速计算基础设施最致命的物理瓶颈。

在现有的自回归解码过程中，GPU 推理被割裂为完全异构的两个阶段：
1. **预填充阶段（Prefill Phase）**：模型将输入的 Prompt 进行全局并行处理，本质上是密集的矩阵乘法（GEMM）。此时算术强度极高，GPU 的 Tensor Core 得以满负荷运转。
2. **解码阶段（Decode Phase）**：模型每产生一个 Token，必须执行一次极其低效的矩阵-向量乘法（GEMV）。为了计算第 $t+1$ 个 Token 的概率分布，硬件必须将全量模型权重以及此前所有 Token 的 Key 和 Value 向量从显存（HBM）完整搬运至片上高速缓存（SRAM）中。

自回归模型 KV Cache 的显存占用随批处理大小（$B$）、序列长度（$S$）、网络层数（$L$）、注意力头数（$H$）以及头维度（$D$）呈刚性线性增长：

$$\text{Memory}_{\text{KV}} = 4 \times B \times L \times H \times D \times S \quad \text{字节（基于 FP16 精度）}$$

当上下文拉长至 128K 乃至 260K 时，KV Cache 的体积会呈爆炸式膨胀，迅速反超模型本身的权重体积。在一套搭载 8 张 NVIDIA H100 SXM5（总显存 640GB HBM3，单卡带宽 3.35 TB/s）的服务器集群中，并发处理上下文超过 10 万 Token 的 70B 模型时，GPU 算力尚未榨出两成，显存早已被狂涨的 KV Cache 吃死。即便引入分组查询注意力（GQA）、PagedAttention 以及极端的 FP8 缓存量化，GPU 在解码时仍有超过 85% 的时钟周期处于“等待数据从内存搬运过来”的闲置停顿状态，单字节数据传输支撑的浮点计算量（算术强度）跌至 1.5 FLOPs/Byte 以下。

知名半导体智库 SemiAnalysis 首席分析师 Dylan Patel 直言当下算力产业的荒诞困境：
> “现代超大规模数据中心的资本支出存在根本性的配置扭曲。我们为每张 GPU 支付数万美元，根本不是因为我们的浮点算力不够用，而是因为自回归解码是一个像高炉炼铁一样狂烧内存带宽的算法陷阱。一旦有一种架构能在维持密集计算的同时斩断动态 KV Cache 的锁链，整个 AI 推理的经济学模型将在瞬间被彻底颠覆。”

Mercury 2.5 撕碎的正是这套旧秩序。由于其去噪过程直接在整段序列或宏观序列块上并行展开，模型的每一次前向推进都是完全批处理化的矩阵乘法（GEMM）。双向 Transformer 仅需在初始阶段对 Prompt 上下文提取一次静态特征表示，整个生成周期中彻底杜绝了动态扩张的庞大 KV 缓存。算术强度直接跃迁至计算受限（Compute-Bound）区间，让普通 H100 与 H200 加速卡全面跑满峰值 FLOPS，最终轰出单流 **1107 tokens/s** 的前所未见速度。

### 技术机制：在离散符号空间实现连续去噪

文本天然是离散、不可微且高度分立的。早期尝试文本扩散的研究（如 D3PM 与 Diffusion-LM）大多折戟于致命的**“舍入坍塌问题”（Rounding Problem）**——在连续的潜空间向量与离散词表空间 $\mathcal{V}$ 之间进行映射投影时，模型极易陷入灾难性的语义漂移、子词无限复读以及语法解构崩溃。

Inception Labs 的核心技术突围，是将 Mercury 2.5 构建为**嵌入空间中的连续分值匹配扩散模型**，并配合经过知识蒸馏标定的投影动力学机制。

```
正向加噪轨迹 (Forward Process t=0 -> t=1)
干净嵌入向量 x_0 ──► 注入高斯扰动序列 ──► 各向同性纯噪声 x_1 ~ N(0, I)

逆向求解轨迹 (Reverse Sampling t=1 -> t=0)
纯噪声 x_1 ──► [高阶连续 ODE 求解器] ──► 曲率调度 ──► 纯净嵌入 x_0 ──► 校准余弦单纯形投影 ──► 离散词元
```

#### 1. 连续嵌入空间的分值匹配
假设待生成的输出序列长度为 $N$，其拼接后的连续嵌入向量张量表示为 $x_0 \in \mathbb{R}^{N \times d}$。正向扰动过程遵循伊藤随机微分方程（Itô SDE）：

$$\mathrm{d}x_t = f(t)x_t\,\mathrm{d}t + g(t)\,\mathrm{d}w_t$$

在保持方差恒定的约束下，从纯净状态 $x_0$ 到连续时间 $t \in [0, 1]$ 下的加噪状态 $x_t$ 的转移概率核为：

$$q(x_t \mid x_0) = \mathcal{N}\left(x_t;\, \alpha_t x_0,\, \sigma_t^2 \mathbf{I}\right)$$

其中 $\alpha_t = \cos\left(\frac{\pi t}{2}\right)$，$\sigma_t = \sin\left(\frac{\pi t}{2}\right)$，满足 $\alpha_t^2 + \sigma_t^2 = 1$ 的单位方差约束。

模型的核心去噪网络 $s_\theta(x_t, t, c)$ 采用双向 Transformer，在输入上下文 Prompt $c$ 的硬约束下，基于 $L_2$ 分值匹配损失函数，训练其逼近纯净嵌入 $x_0$ 或速度向量 $v_t \equiv \alpha_t \epsilon - \sigma_t x_0$：

$$\mathcal{L}_{\text{diff}}(\theta) = \mathbb{E}_{t, x_0, \epsilon} \left[ \lambda(t) \| s_\theta(x_t, t, c) - v_t \|_2^2 \right]$$

在推理采样时，模型直接以标准高斯白噪声 $x_1 \sim \mathcal{N}(0, \mathbf{I})$ 为起点，通过确定性**概率流常微分方程（Probability Flow ODE）**反向积分求解：

$$\frac{\mathrm{d}x_t}{\mathrm{d}t} = f(t)x_t - \frac{1}{2}g(t)^2 \nabla_{x_t}\log p_t(x_t \mid c)$$

#### 2. 瓦解舍入坍塌：温度校准的单纯形投影
Mercury 2.5 生成质量飞跃的真正秘诀，在于其“连续到离散”的映射桥梁。传统做法在最后一步生硬地将连续向量抓取到最近邻的词表嵌入上，一旦向量游走于两个相近语义词之间，极易导致局部崩塌。

Mercury 2.5 引入了**温度校准的 Softmax 概率单纯形投影（Calibrated Simplex Projection）**：

$$p(w_i = v \mid x_{0, i}) = \frac{\exp\left( \tau^{-1} \cos\left(x_{0, i},\, E_v\right) \right)}{\sum_{v' \in \mathcal{V}} \exp\left( \tau^{-1} \cos\left(x_{0, i},\, E_{v'}\right) \right)}$$

在 ODE 逆向采样的中间求解步骤中，系统完全不执行任何离散量化操作，整个双向 Transformer 始终在平滑的概率密度空间中演化，使模糊的语义歧义以“量子态式的叠加”保留在潜空间中，直到轨迹积分接近端点时才迅速坍缩并锁定为确定性的文本 Token。

#### 3. 引导率与渐进式蒸馏
在传统图像扩散模型中，往往需要依赖较高的无分类器引导尺度（Classifier-Free Guidance, CFG = 4.0 - 7.5），这意味着每一步去噪都必须并行跑“有条件”和“无条件”两次前向传播，让计算成本硬生生翻倍。

Mercury 2.5 采用了多阶段渐进式轨迹蒸馏算法。通过将庞大 Teacher 模型的积分步数极致压缩，研发团队成功将线上推理的 **CFG 引导值固定为 1.0**。这意味着每个去噪步仅需执行单次前向评估，消除了额外的负向提示词开销，真正保住了 1107 tokens/s 的物理极速。

### 工程争论：语义倒置的幽灵与确定性推理的边界

Mercury 2.5 的横空出世，迅速在硅谷开发者圈层与各大实验室之间激化了一场围绕“因果自回归与全局非自回归”哲学路线的白热化争鸣。

```
因果拓扑逻辑的根本分歧

自回归因果拓扑（严格的单向下三角因果掩码）：
[第 1 步：已知条件 A] ──► [第 2 步：推导过程 B] ──► [第 3 步：得出结论 C]
（确保严格的时间因果一致性，单向误差有界传递）

非自回归扩散拓扑（全双向注意力机制）：
[第 1 步：修正 A ◄──► 细化 B ◄──► 推导 C 处于同一时间切片中同步展开]
（在大幅削减求解步数预算时，存在中段语义抖动与逻辑因果倒置的风险）
```

#### 1. 序列中段的“语义倒置”疑云
在自回归体系下，因果性由下三角注意力掩码物理锁死：第 $N$ 个 Token 在物理机制上绝不可能观测或回溯改写第 $N-1$ 个 Token。然而在连续扩散中，由于所有 Token 在每一时间步通过双向自注意力机制完全互视，长程全局信息虽得以畅通，却埋下了隐患。

在 X.com 和 Reddit 的深度技术讨论区中，多位资深系统架构师敏锐地指出了测试中出现的**“中段语义抖动（Mid-sequence Semantic Jitter）”**现象。在为了极限吞吐而采用极度激进的少步数采样调度时，处于复杂长逻辑语法中间位置的 Token 有可能发生局部顺序倒错。例如在复杂的嵌套代码或条件不等式中：

```python
if (min_val <= current_val and current_val < max_val):
```

某些扩散求解轨迹会在关系运算符尚未完全脱离噪声形态之前，过早锁定了下游的变量名，生成诸如 `if (max_val <= current_val and ...)` 这类因果颠倒的临时伪影。虽然在给予充分的 ODE 积分步数时模型能够自我纠偏，但在高并发、追求极致速度的工业级推理截断下，这种离散符号约束的局部破坏偶有残留。

康奈尔理工学院教授、Hugging Face 科学负责人 Sasha Rush 直击其本质矛盾：
> “自回归赋予了语言模型一种不可或缺的归纳偏置（Inductive Bias）：时间上的因果流动与演绎逻辑的前后推演在拓扑结构上是严格同构的。当你把语言暴力拍进连续扩散空间，你实际上是强求一个连续分值网络在一瞬间去求解一个全局的离散约束满足问题。一旦积分求解器的计算预算被强制掐断，语言句法就会出现自回归模型绝不可能发生的非局部解构。”

#### 2. 演绎逻辑与思维链（Chain-of-Thought）的本质归宿
另一个备受瞩目的交锋点在于：扩散架构能重现 OpenAI o1 或 Gemini 2.0 展现出的深层测试时推理能力吗？

在以 o1 为代表的自回归体系中，“推理”被物化为**序列长度维度上的显式测试时计算（Test-Time Compute）**——通过展开数千个思维链 Token，让每一步前置的思考成为后一步严格的因果锚点。而在 Mercury 2.5 中，测试时计算转移到了**去噪深度维度（ODE 积分求解步数）**。

斯坦福大学教授兼 Inception Labs 联合创始人 Stefano Ermon 在近期的一场系统闭门峰会上据理力争：
> “将人类的思考等同于严格单向的自回归流式吐字，是把人类的发声器官生理局限当成了大脑皮层的认知机制。顶尖工程师编写复杂架构或者数学家构建高难度证明时，从来都是先在脑海中勾勒宏观的高阶抽象意图，再去推敲细枝末节的词元语法。自回归模型最大的死穴是不可逆的复合误差——如果在第 5 步选错了一个 Token，到了第 100 步整个逻辑分支就彻底万劫不复。Mercury 2.5 是在全局流行流形上同步推演，拥有在整个去噪周期中实时纠正早期中间错误的容错机制。”

Inception Labs 早期投资人、前特斯拉 AI 总监 Andrej Karpathy 在 X.com 上给出了客观评价：
> “基于扩散的 LLM 是对自回归帝国发起的第一次真正具备商业破坏力的正面强攻。干掉串行的 KV Cache 数据搬运所带来的吞吐量提升是惊人的。现在唯一的终极悬念在于：连续松弛算法能否完美且稳定地收敛严密脆弱的确定性算法依赖（即每一个 Token 都是上一个 Token 的严格离散函数），而不至于在离散代码中引入连续空间的幽灵伪影。”

图灵奖得主、Meta 首席 AI 科学家 Yann LeCun 亦再次重申了他对自回归的清算态度：
> “自回归生成的根本缺陷就在于指数级放大的复合误差。探索连续空间中基于分值与能量的模型表征，是通往全局表征规划的必经之路，唯有如此才能摆脱现在这种高维‘俄罗斯轮盘赌’式的单字押宝。”

### 商业落地：扩散架构能否全面取代 Transformer？

Inception Labs 从未将 Mercury 2.5 定义为一个学术玩具，而是直接将其锻造为企业级生产环境中可直接替换现有模型的工业重器。

| 核心架构维度 | 传统主流自回归模型（如 Llama 3.3 70B / Claude 3.5 Haiku） | Inception Labs Mercury 2.5（连续扩散架构） |
| :--- | :--- | :--- |
| **单流解码吞吐速度** | 40 – 95 tokens/秒 | **1,107 tokens/秒** |
| **底层硬件性能瓶颈** | 内存带宽受限（深陷 HBM 读写延迟） | **算力受限（充分吃满 Tensor Core 吞吐）** |
| **KV Cache 显存占用** | 随生成序列长度线性暴增（$\mathcal{O}(S)$） | **仅需固定 Prompt 静态分配（动态扩增为 $\mathcal{O}(1)$）** |
| **上下文窗口支持** | 128K – 200K tokens | **260K tokens** |
| **代码上下文填空（FIM）** | 依赖复杂的数据微调与特殊 Prefix/Suffix 提示模板 | **原生支持全双向条件掩码修补** |
| **推理逻辑展开维度** | 串行展开显式 Token 思维链长度 | **迭代执行连续 ODE 去噪轨迹步数** |
| **核心基准得分（MMLU-Pro）**| 78% – 85%（Haiku / Flash 水平） | **最高可达 89.4%（视推理步数配置而定）** |
| **API 调用计费标准** | 0.80 – 2.00 美元 / 百万输出 Token | **0.75 美元 / 百万输出 Token（输入仅 0.20 美元）** |

```
真实推理延迟对比（生成 200 个 Token 的 Agent 工具调用）
传统自回归 (60 tok/s):  ████████████████████████████████ 3,333 毫秒
Mercury 2.5 (1,107 tok/s): █ 180 毫秒
```

在具体的生产级工作负载中，Mercury 2.5 正在重塑三个核心阵地：

1. **亚秒级自主 Agent 实时闭环**：
   当代基于工具调用的多 Agent 智能体架构中，系统每走一步都需要等待模型吐出一段格式化代码或 SQL 查询。传统自回归模型输出一段 200 Token 的工具指令耗时高达 3.3 秒，多轮交互下来系统延迟极度恶化；Mercury 2.5 将这一耗时压缩至 **180 毫秒**，第一次让多智能体协作从“迟钝的离线异步脚本”进化为“无感响应的交互式实时系统”。

2. **原生全双向代码修改与局部重构（Infilling）**：
   在真实的软件开发中，开发者几乎从不在文件的最末尾单向追加代码，而是频繁在现有抽象语法树（AST）的上下文间进行局部插拔修改。自回归模型在处理这类“代码中间填空（FIM）”任务时必须借由晦涩的人工提示词前缀将上下文割裂，而 Mercury 2.5 天生支持双向掩码，只需将外层上下文特征冻结，即可直接在中间缺损的 Token 槽位上并行扩散去噪。

3. **海量超长文本的信息提取**：
   面对法律合规审计、医疗病历结构化分析以及 260K 超长金融财报的批量抽取任务，企业原有的 GPU 集群通常会因为数十个并发用户的动态 KV Cache 瞬间打爆 VRAM。Mercury 2.5 极度固定的显存占位特征，使得高密度推理节点可以在彻底杜绝显存溢出（OOM）崩溃的前提下，将整机 GPU 算力压榨至极限。

### 终局裁决

Mercury 2.5 的发布，正式宣告了自回归 Transformer 独霸 LLM 商业王座时代的终结。它用扎实的数据证明：非自回归连续扩散完全能够实现 **1107 tokens/s** 的工业级吐字速度，并在复杂学术评测中击穿近 90% 的顶级基准线，强行撞开了横亘在 AI 芯片设计前沿整整七年的内存高墙。

但这并不意味着自回归架构的全面覆灭。

在需要极其严丝合缝、每一步逻辑推导绝对不容丝毫语法坍塌的纯确定性形式化数学证明与深层因果任务中，单向因果掩码铸就的自回归模型仍然是历经最严酷考验的稳定防线。

在可见的未来，AI 计算范式正在走向一种高效的异构协同：由顶尖的自回归模型坐镇决策高阁，担任负责深思熟虑的慢思考规划者；而将海量的并行文本生成、亚秒级 Agent 工具调度与双向代码填充，全面下放给以 Mercury 2.5 为代表、快如闪电的扩散推理引擎。
