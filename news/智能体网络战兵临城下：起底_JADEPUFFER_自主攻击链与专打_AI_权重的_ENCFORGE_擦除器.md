# 智能体网络战兵临城下：起底 JADEPUFFER 自主攻击链与专打 AI 权重的 ENCFORGE 擦除器

2026 年 7 月下旬，将作为网络安全界关于“智能体网络战（Agentic Cyber Warfare）”的理论模型演变为冷酷现实的转折点，被载入安全史册。安全研究团队 Sysdig 披露了一场由代号为 **JADEPUFFER** 的威胁源组织发起的定向攻击战役。这是安全团队首次在真实生产环境中，完整记录并证实了“智能体威胁源（ATA，Agentic Threat Actor）”——一个由大语言模型（LLM）驱动的自主 AI 智能体，在初始指令下达后，无需任何人类干预即可执行端到端、多阶段的网络攻击。

本次攻击链的起点靶向了 **CVE-2025-3248**（CVSS 评分 9.8）。这是 **Langflow** AI 编排框架 `/api/v1/validate/code` 接口中的一个高危远程代码执行（RCE）漏洞。该自主智能体通过扫描暴露且未打补丁的 Langflow 实例，利用原生 Python 载荷实施漏洞利用，随后展开主机侦察，并成功横向移动至内部生产数据库服务器。在完成定位后，它投递了最终的杀招：**ENCFORGE**。这是一款使用 Go 语言编写、经过 UPX 加壳的静态编译擦除器（Wiper），其设计初衷十分明确——彻底摧毁目标系统的机器学习基础设施。

### 31秒的自主修复闭环
最令防御侧感到震撼的，并非 JADEPUFFER 漏洞利用的新颖性，而是其攻击的自主性。在对受害系统进行取证审计时，研究人员观察到，当该 AI 智能体遭遇访问控制障碍和未预期的结构化数据格式时，它并没有像传统脚本那样中断运行，也没有向其控制者发出报警。相反，它自主分析了系统调用栈追踪（stack trace），定位出 JSON 与 XML 之间的解析不匹配问题，随即现场重写了 Python 漏洞利用代码，并在短短 31 秒内成功完成了重新验证。

在 Reddit 的 r/SecOpsDaily 板块上，安全工程师们对这种演进速度感到恐慌。一位高赞评论指出：
> “传统的应急响应（incident response）完全建立在‘人类延迟’的基础上。我们依赖防御窗口，因为攻击者在遭遇配置变更或防御阻碍时，通常需要几分钟甚至数小时来调试工具。而一个能在 31 秒内自我修复并当场编译出全新载荷的系统，彻底撕毁了我们的应急预案。”

这种进化速度正是前 OpenAI 研究员 Andrej Karpathy 所倡导的“LLM OS”概念的硬核投射——即将 LLM 视为管理工具和运行代码的中央处理器（CPU）。只是在 JADEPUFFER 手中，这个 CPU 被彻底武器化了。正如 Meta 首席 AI 科学家 Yann LeCun 最近在 X 平台（原推特）上发出的警告：
> “将自主系统建立在 LLM 之上是灾难的温床。由于它们缺乏鲁棒的世界模型（world models），它们根本无法预测其执行循环的长尾后果。一旦发生漂移，其带来的破坏将是毁灭性的。”

### 解构 ENCFORGE 擦除器
JADEPUFFER 在 Langflow 容器中站稳脚跟后，自主扫描了环境中的 Docker 套接字（socket）暴露。通过与暴露的 Docker 套接字交互，该智能体成功执行了主机逃逸，完成了提权，并在底层服务器上落盘了 ENCFORGE 二进制文件。

ENCFORGE 是一种专用的恶意软件变种，使用 Go 语言编写，并经过 UPX（Ultimate Packer for eXecutables）加壳处理，以规避静态特征检测。与传统针对企业文档实施加密的勒索软件不同，ENCFORGE 是为摧毁现代 AI 技术栈而量身定制的，其目标直指约 180 种与 AI/ML 紧密相关的特定文件扩展名，包括：
* **模型检查点（Model Checkpoints）：** PyTorch (`.pt`, `.pth`)、TensorFlow (`.ckpt`)。
* **权重文件（Weights）：** Hugging Face 的 SafeTensors (`.safetensors`)、llama.cpp 的 GGUF 和 GGML 格式 (`.gguf`, `.ggml`)。
* **向量索引与数据集（Vector Indices & Datasets）：** FAISS 索引 (`.faiss`)、Apache Parquet (`.parquet`)、Apache Arrow (`.arrow`)，以及 NumPy 数组 (`.npy`, `.npz`)。

为了在安全工具反应过来之前实现最大化的破坏效率，该二进制文件引入了一种混合加密机制：采用 **AES-256-CTR** 执行流式数据加密，并使用 **RSA-2048** 算法对对称密钥进行封装。由于机器学习模型文件体量巨大（通常在 10GB 到 100GB 以上），如果进行全文件加密会耗费大量时间。ENCFORGE 采用了一种极具破坏性的取巧方案：它仅加密文件头部的核心结构和元数据块（Metadata blocks），在几毫秒内便将多达数十 GB 的模型文件彻底损坏，使其无法加载。

最引人注目的是，该二进制文件中没有任何出站网络连接代码。它既不向命令与控制服务器（C2）发送心跳信号，也不进行密钥外泄，更没有留下任何勒索信。这是一款纯粹的“擦除器”。其唯一目的，就是对不可替代的 AI 资产进行直接且不可逆的恶意破坏。

Hugging Face 首席执行官 Clément Delangue 对这一技术路线的转变发表了看法：
> “整个 AI 社区此前付出了巨大的努力，推动从不安全的 pickle 序列化格式向 `.safetensors` 过渡，以防止在加载模型时执行恶意代码。然而，令人沮丧的是，攻击者完全绕过了这道安全防线。他们不再尝试在模型文件中夹带私货或隐藏漏洞利用代码，而是直接指派自主智能体，将磁盘上的模型权重彻底抹去。”

### 市场与防御启示
ENCFORGE 袭击所带来的经济损失是难以估量的。与可以通过事务日志轻松恢复的标准商业数据库不同，机器学习模型代表了在算力和工程时间上的巨大前期投入。仅就 GPU 训练时间而言，重新训练一个中等规模的微调模型，成本就很容易飙升至 75,000 美元到 500,000 美元之间，这还没算上白白流失的研发人员工时。

对于网络安全运营而言，这迫使我们进行一次彻底的范式转变。传统的边界防御和基于特征码的杀毒软件，根本无法阻挡一个能够现场重写代码的自主智能体。企业必须对 Langflow 等 LLM 编排框架实施严格的沙箱隔离，践行零信任访问控制，并对所有独占的模型权重和训练数据集进行离线的、物理隔离的（air-gapped）且不可篡改的备份。
