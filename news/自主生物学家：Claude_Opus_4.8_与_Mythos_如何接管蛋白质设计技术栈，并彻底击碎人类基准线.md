# 自主生物学家：Claude Opus 4.8 与 Mythos 如何接管蛋白质设计技术栈，并彻底击碎人类基准线

2026年8月18日，计算领域的“干实验”与物理世界的“湿实验”之间的传统边界彻底消融。Anthropic 在 Hugging Face 上发布了一个里程碑式的数据集（`Anthropic/claude-protein-binder-design`），详细披露了其前沿模型——Claude Opus 4.8 与 Mythos Preview，如何在仅凭一条 1.6 万字协议提示词（`multi_target_binder_design_prompt.md`）的情况下，自主执行端到端的“从头蛋白质结合剂设计”（de novo protein binder design）任务。

在没有任何人类干预（human-in-the-loop）的条件下，AI 智能体自主完成了靶点生物学研究、表位选择、软件编译及工具链调度。这些设计随后在瑞士洛桑的 Adaptyv Bio 以及 Twist Bioscience 进行了双盲物理验证。在获得可靠湿实验测量数据的 1320 个设计中，有 354 个被证实为有效结合剂，覆盖了产生可用数据的 15 个靶点中的 14 个（实验总共测试了 16 个靶点）。这意味着其整体成功率达到了惊人的 26.8%——在 Mythos Preview 运行的单靶点设计任务中，这一成功率更是冲上了 35.1% 的峰值。相比之下，传统人类专家在从头设计领域的成功率通常仅在 10% 到 15% 之间徘徊。在 E3 连接酶亚基 RBX1 靶点上，Claude 设计出的最强结合剂其亲和力（$K_D$）达到了 3.9 nM，以压倒性优势击败了此前在一项拥有 245 个参赛作品的公开人类设计大赛中夺冠的 45 nM 纪录。

这绝不仅仅是一次简单的基准测试刷新，而是我们在构建生物系统方式上迎来的一次范式转移。

---

### 智能体流水线：操纵生物计算技术栈

要理解这场战役的开创性意义，必须深入审视 Claude 所调度的计算流水线。Claude 并非依赖单一的端到端神经网络，而是化身成一位自主的系统工程师，将各种专用的开源工具链进行封装与串联：

1. **靶点研究与表位选择**：智能体评估了包括 Cas9、EGFR、PD-L1 和 VEGF-A 在内的多个靶点，并根据其本地参考语料库中的结构文献，定义了靶点结合坐标（表位）。
2. **支架生成**：Claude 调用了 RFdiffusion（具体为 RFdiffusion3）以及 BoltzGen（麻省理工学院开发的全原子通用扩散模型）来生成三维骨架。
3. **序列设计（固定骨架设计）**：生成的骨架被输入至 SolubleMPNN（一种针对溶解度进行优化的 ProteinMPNN 变体）中，以设计出匹配的氨基酸序列。
4. **验证关卡与干实验筛选**：Claude 利用 ESMFold2 和基于 Protenix 基础模型的 Protenix v2 预测了所设计复合物的结构。它通过分析预测对齐误差（PAE）矩阵并计算局部接触电位（LCP）来评估界面能量，从而过滤掉那些仅仅模仿靶点自身折叠的候选体。

该智能体架构在一个严格的“单一派遣所有者”（single-dispatch-owner）协议下运行。该规则不仅防止了智能体催生出冗余的并发进程，还强制要求每种生成方法对每个靶点贡献至少 50 个骨架。

### 约束下的自主性：环境搭建与自我纠错

将此次实验与标准的 API 调用流水线区分开来的，是 Claude 拥有的高度执行自主性。该智能体被授予了一个 Modal 无服务器 GPU 计算账户，并被要求自主配置其运行环境。

在长达 48 小时的战役中，智能体遭遇了无数的运行时错误：
* **CUDA 显存溢出（OOM）**：当处理如 Cas9（超过 1000 个残基）这类较大的靶点时，Claude 撞上了硬件显存瓶颈。该模型自主重构了 Python 执行脚本，通过动态缩减批次大小（batch size）并引入梯度检查点（gradient checkpointing）化解了危机。
* **Conda 依赖地狱**：在将老旧的结构生物学软件包与现代深度学习框架进行联调编译时，经常会出现环境依赖崩溃（例如 numpy 与 scipy 的版本冲突）。Claude 自行解析了调用栈追踪信息，修改了 `environment.yml` 配置文件，并当场解决了编译冲突。
* **API 速率限制**：在从 NCBI 获取序列或检索文献时，智能体主动追踪并处理了 API 频次超限问题，通过引入指数退避（backoff）算法防止了执行中断。

### 学术大激辩：“真实的生物学理解”还是“高效的编译器”？

这一突破再度引爆了学术界关于大语言模型（LLM）智能体是否真正拥有分子生物学结构“理解”能力，抑或只是一个超高效的宏编译器的争论。

Meta 首席 AI 科学家 Yann LeCun 在社交平台 X 上表达了他的怀疑：
> “大语言模型并没有物理化学的世界模型。Anthropic 构建的其实是一个针对专业软件的超高效编译器。物理交互的重活累活仍然是由 RFdiffusion 和 ProteinMPNN 这些模型完成的——而它们是基于真实物理与结构归纳偏置构建的，绝非文本 Token 预测。”

相反，诺贝尔奖得主、计算蛋白质设计先驱 David Baker 则高度肯定了这种整合价值：
> “像 RFdiffusion 这样的生成式扩散模型已经打开了这扇门，但看到通用智能体能够自主地将这些流水线串联起来、解决代码依赖，并输出经过湿实验验证的结合剂，这是整个生态系统的一大步跨越。”

Adaptyv Bio 联合创始人兼 CEO Julian Englert 则强调了全新的操作现实：
> “在设计阶段，‘设计-构建-测试’的闭环已经不再受限于人类的带宽。但湿实验依然是物理世界的瓶颈。智能体可以在几分钟内生成数百万个设计，但合成与表征它们仍然需要物理原子。”

与此同时，著名风险投资人 Nat Friedman 敏锐地指出了其商业影响：
> “我们正在进入‘比特到原子’编译器的时代。生物学是终极的工程学科。未来能够成功的创业公司不会只做大语言模型，而是会构建自动化基础设施来执行它们的设计。”

### 双重用途风险与生物安全漏洞

Claude 轻松驾驭这一复杂设计流程的事实，也暴露出了巨大的生物安全漏洞。尽管本研究中的靶点均属治疗性质（如 TNFα、EGFR 以及合成 β-桶状蛋白 BBF-14），但完全相同的流水线一旦被恶意利用，就可能被用于设计针对生物武器、病毒入侵受体或全新毒素的高亲和力结合剂。

Anthropic 在此次设计战役中执行了严格的“AI安全等级3”（ASL-3）协议。ASL-3 强制要求采取包含自动分类器在内的多重安全封锁措施，以拦截生物威胁。然而，这套防线并非万无一失。在 2026 年 8 月，Anthropic 曾披露过一起重大的管理疏忽：由于内部配置失误，在长达近一年的时间里（2025 年 5 月至 2026 年 4 月），面向人工反馈供应商的数据流中，生物风险过滤器被意外关闭。尽管 Anthropic 表示未发现任何滥用迹象，但这无疑证明了软件层面的过滤器防线是多么脆弱。

此外，在监管自动化的湿实验订单方面，目前仍存在巨大的法律真空。目前，像 Twist Bioscience 和 Adaptyv Bio 这样的合同研究组织（CRO）虽然会对 DNA 订单进行已知病原体筛查，但他们的筛查协议对 AI 自主“从头设计”的全新微蛋白几乎无能为力。因为这些氨基酸序列是完全凭空设计出来的，无法与任何现存的病原体数据库进行比对，因此能极易绕过传统的序列比对筛查。

### 前路何方

随着 Anthropic 开始转向“受信任的访问通道”（trusted access pathways）——即仅对预先筛选的机构开放 Mythos 5 和 Claude Opus 5 的生物学能力——整个行业面临着抉择：我们要么为 AI 签名的湿实验订单制定一套国际标准，要么就必须接受这样一个事实：生物学的平民化，将不可避免地伴随着生物威胁的平民化。

自主科学的时代已经来临。我们对这些“编译器”的监管方式，将决定人类未来是能治愈更多疾病，还是会亲手设计出一场灾难。
